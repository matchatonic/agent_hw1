# Спецификация трекера

## Requirement: автономность и поставка

Приложение MUST работать без CDN, внешних библиотек и API-ключей.
Состав файлов MUST соответствовать выбранному варианту A или B,
описанному в proposal.md.

### Scenario: автономная работа
- WHEN приложение используется без доступа к внешним ресурсам
- THEN добавление, удаление, переключение done, фильтрация и расчёты работают.

## Requirement: данные и начальное состояние

Каждая задача MUST содержать id, title, hours и done.
Стартовый пример MUST содержать «Чтение» — 2 ч, done=true;
«Практика» — 4 ч, done=false; «Повторение» — 2 ч, done=false.

### Scenario: стартовый пример
- WHEN загружен стартовый пример
- THEN всего отображается 8 ч, выполнено 2 ч, прогресс 25%.

## Requirement: изменение задач

Добавление, удаление и переключение done MUST изменять данные задач,
а интерфейс MUST отражать актуальные данные.

### Scenario: добавление
- WHEN отправлена форма с допустимым названием и допустимыми часами
- THEN в данные добавляется задача с уникальным id, названием после trim,
  указанными часами и done=false
- THEN список и сводные показатели обновляются.

### Scenario: удаление
- WHEN пользователь удаляет задачу
- THEN задача удаляется из данных
- THEN список и сводные показатели обновляются.

### Scenario: переключение выполнения
- WHEN «Практика» в стартовом примере отмечена готовой
- THEN её done становится true
- THEN выполнено 6 из 8 ч, прогресс 75%.

### Scenario: обратное переключение
- WHEN «Практика» снова отмечена невыполненной
- THEN её done становится false
- THEN выполнено 2 из 8 ч, прогресс 25%.

## Requirement: проверка формы

Название после trim MUST быть непустым.
Часы MUST быть числом от 0,5 до 24 включительно с шагом 0,5.
Пустое значение часов MUST считаться ошибкой, а не нулём.

При ошибке задача MUST NOT добавляться; ошибка MUST быть видна рядом
с соответствующим полем; введённые значения формы MUST сохраняться.

### Scenario: пустое название
- WHEN отправлено пустое название или название только из пробелов
- THEN задача не добавляется
- THEN рядом с названием видна ошибка, значения формы сохраняются.

### Scenario: недопустимые часы
- WHEN отправлены пустые, нечисловые, отрицательные часы, ноль,
  значение вне диапазона 0,5–24 или значение не с шагом 0,5
- THEN задача не добавляется
- THEN рядом с часами видна ошибка, значения формы сохраняются.

### Scenario: допустимые границы
- WHEN отправлено непустое название и часы 0,5 или 24
- THEN задача добавляется.

## Requirement: расчёт итогов

Итоговые часы и прогресс MUST рассчитываться по всем задачам.
Прогресс MUST равняться округлению до ближайшего целого значения
100 × выполненные часы / все часы.
При отсутствии задач итог MUST быть 0 ч, прогресс MUST быть 0%;
NaN и Infinity MUST NOT отображаться.

### Scenario: все задачи удалены
- WHEN удалена последняя задача
- THEN всего 0 ч, выполнено 0 ч, прогресс 0%.

## Requirement: фильтрация

Фильтр MUST влиять только на видимый список и MUST NOT изменять
данные задач или область расчёта итогов.

### Scenario: активные задачи
- WHEN в стартовом примере включён фильтр «активные»
- THEN видны только «Практика» и «Повторение»
- THEN всего остаётся 8 ч, выполнено 2 ч, прогресс 25%.

## Requirement: читаемость и подписи

Интерфейс MUST быть читаемым на ширине 390 px без горизонтального
скролла. Поля и кнопки MUST иметь понятные подписи.

### Scenario: узкий экран
- WHEN ширина области просмотра составляет 390 px
- THEN содержимое и элементы управления доступны без горизонтального скролла
- THEN назначение полей и кнопок понятно из подписей.

## Необязательное расширение: localStorage

Если сохранение реализовано, приложение MUST восстанавливать сохранённые
задачи и сохранять изменения. При недоступности хранилища оно MUST
показывать понятное сообщение и продолжать работу в памяти.

### Scenario: восстановление сохранённых задач
- WHEN хранилище доступно и содержит ранее сохранённые задачи
- THEN приложение восстанавливает эти задачи.

### Scenario: недоступное хранилище
- WHEN чтение или запись localStorage недоступны
- THEN пользователь видит понятное сообщение
- THEN операции с задачами продолжают работать в памяти.
